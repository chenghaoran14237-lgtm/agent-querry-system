# 医疗场景应用生成平台：实施方案

更新：2026-09-08。依据 [分层接口复核](ONLINE_API_AUDIT_2026-09-08.md) 和本地代码审计。本文描述目标架构，不代表全部已实现。本轮只补充审计工具、修正文档，没有修改现有运行代码或 UI。

## 1. 需求和定位

产品保持用户指定的三部分：

1. 选择并连接远端数据源。
2. 描述业务需求，生成系统并调整。
3. 使用已持久化的生成系统，按授权操作远端数据。

医疗平台是当前接入对象和验证场景，不把产品固定成床位控制台，也不试图替代整个 HIS。生成什么模块由用户需求、真实字段、关系和权限共同决定。床位表只是已有元数据测试用例，不是最终产品范围。

目标包括方便使用的查询和 CRUD，但未经验证的操作必须显示未接通。RAG 帮助理解资料，不替代数据库连接、授权、实时数据和事务服务。

继续使用现有 buildkit-platform 目录，不新建重复 Demo。当前实现准确名称是“网站登录态接入 + 应用定义生成 + 脱敏样例预览”。

## 2. 必须区分的能力边界

| 层 | 当前证据 | 约束 |
| --- | --- | --- |
| 内部管理/登录态 API | 登录、数据源、画像、样例、关系等 GET 已成功 | 管理员能调用不等于外部客户有这些权限 |
| External v1 | 手册定义会话、运行、事件、动作和产物 | 当前可见部门应用没有可用外部部署候选，未端到端验收 |
| 具体部署固定版本 | 应用 17 版本 25 无工具/MCP/知识库；草稿另有知识库 | 名字、草稿和 healthy/ready 不能替代已发布能力 |

最早直接发现的阻塞是 buildkit-demo-test 部署停用；凭证禁用、API origin 缺失、固定版本缺少数据工具是后续独立缺口。未发运行请求，不能将其描述为模型或 SSE 运行失败。

平台内部已有查询运行和结果分页定义。真正待补齐的是“获准的外部调用方式 + 稳定查询契约 + 本地运行验收”，而不是笼统说平台没有查询。业务写权限也不能从元数据 PATCH、Actions 或工具名称中推导。

## 3. 页面与交互

### 数据连接：/connections

- 默认选择平台已注册且当前用户获准的数据源，不在本地收集数据库超级用户密码。
- 分开浏览资产、确认选用、管理连接。查看表不能覆盖持久化选择。
- 展示连接健康、画像时间、目录和实际能力。未知授权显示待核验，不能自动视为可写。
- 目录支持服务端分页/搜索；按保存的精确表标识恢复，不依赖第一页或默认床位表。
- 表详情展示真实字段、类型、主键、约束、注释、敏感标记和关联证据。
- “画像样例”与“业务查询”分开入口，样例显示画像日期和采样数量。
- 新注册数据库属于平台管理员流程；契约未开放时指向该流程，不在本地复制未经批准的管理能力。

### 生成工作室：/builder/:draftId

- 左侧需求对话，右侧以系统预览为主；顶部显示绑定与权限。
- 首轮确认对象、字段、筛选、详情和拟用操作；缺字段或关系时明确提问。
- 区分理解需求、生成、校验、可预览、失败、等待输入/审批。
- AppSpec 校验后保存草稿；修改先显示差异，不覆盖已发布版本。
- 主要操作：保存草稿、预览、发布。发布需用户显式触发。
- 技术证据默认折叠，但错误和待处理动作不可隐藏；审批不自动同意。

### 系统中心：/apps 与 /apps/:id

- 列表展示系统名称、来源、草稿/发布状态、版本、数据模式和允许动作。
- 打开后业务页面占主体：紧凑导航、标题、查询栏、表格、分页、详情抽屉。
- 新增/编辑由字段类型生成表单；删除单独确认；成功只在远端确认提交后显示。
- 读取、详情、新增、编辑、删除、导入、导出分别由后端能力决定可用性。
- 数据模式明确为画像样例或远端查询结果，不统称“实时数据”。
- 查询失败显示可行动错误；不回退到本地假数据或把旧样例当最新结果。

业务组件需要事实依据。bed_master 当前 9 个字段没有院区、当前患者、入出院状态；status-1 不能解释为空闲/占用。床位主数据维护不是床位调度，也不是患者转床。关联患者等功能只有在对应字段、可信关系和权限具备后才加入。

## 4. 技术架构

~~~text
Web：连接中心 / 生成工作室 / 已发布系统
                      │
本地后端：身份授权 / 能力注册 / Spec 校验 / 版本 / 作业
       │                 │                 │
CatalogGateway      AgentGateway       DataGateway
       │                 │              ├─ Query
获准的元数据契约    外部部署固定版本       └─ Mutation
       └─────────────────┴─────────────────┘
                     线上医疗平台

本地：应用定义、连接引用、不可变版本、作业与脱敏审计
远端：业务记录，经获准的数据服务读取和写回
~~~

Catalog、Agent、Query、Mutation 独立配置、独立健康状态；不能因环境变量存在 Key 就隐式切换协议。登录态适配器只用于明确标识的开发诊断，不作为绕过 External v1 的生产后门。

构建者负责选择资产、生成和发布；业务使用者按自己权限运行。不能为所有使用者透传共享管理员身份。部门 ID 不自动等同病区/院区数据权限。

工程上先提取现有 Python 代码中的 Gateway、Service、Repository、Validator；部署版建议 FastAPI/SQLAlchemy、React/TypeScript、PostgreSQL 与明确的任务执行服务。本地可用 SQLite。这是技术建议，尚未安装这些依赖或进行迁移。

## 5. 生成协议和能力校验

AppSpec 只描述组件与绑定，不含可执行 JS、任意 HTML/SQL、凭证或任意网络地址。

建议 v2 内容：

~~~text
schema_version, name, description
bindings[]: connection_ref, source_id, schema, table, profile_run_id, fingerprint
pages[]: route, title, components, fields, filters, sort, detail
requested_operations[]: read, create, update, delete, import, export
validation_summary, source_references
~~~

requested_operations 是模型的请求，不是授权。实际允许动作由服务器计算：

~~~text
模型请求 ∩ 已验证网关能力 ∩ 用户/范围授权 ∩ 当前业务状态
~~~

未知取禁止；前后端都执行，禁用按钮不是安全控制。主键、默认值、可写字段取自可信契约。RAG 文本和工具返回是资料，不能改变约束或发起越权动作。

正式生成建议使用独立 Builder 角色、固定发布版本和服务端工具白名单。提示词中的“不要调用工具”不是权限控制；不能给 Builder 医疗写权限。是否创建和开放该部署需要平台负责人确认，不直接修改现有应用。

## 6. 数据接口契约

以下是本项目所需规格，不是已经存在的线上端点。实现可由平台正式 REST 或获准的结构化工具提供，无需重复造服务；不能擅自直连数据库绕过平台治理。

### QueryGateway

- 输入：发布版本、实体绑定、字段白名单、类型化筛选、稳定排序、游标/limit。
- 输出：列、行、来源、执行标识、读取时间、snapshot/游标、has_more。
- total 标明精确/估算/未知；分页固定结果集与每次重查远端必须区分。
- 明确结果集过期、刷新、取消、查询超时和限流。
- 详情以稳定主键定位，不把样例行当真实详情。
- 关联候选/字典单独限量查询；跨库 join 需授权和可解释关系。
- 错误区分认证过期、无权限、结构变化、超时、限流、结果过期；不暴露连接密钥。

### MutationGateway

- 输入：获准实体/业务命令、稳定主键、可写字段、Idempotency-Key、expected_version/ETag。
- 输出：受影响记录/新版本、服务器时间、操作审计 ID；模型文字“成功”不能作为提交证据。
- 同键不同内容冲突；旧版本冲突，不静默覆盖。
- 服务端实施类型、必填、业务规则校验与事务。
- 转床、入院、出院等跨表工作流用独立业务命令，不当普通字段更新。
- 删除/软删除/恢复规则由业务负责人定义；导入先预检影响，再确认提交。
- 明确审批、行列权限、事务、失败回滚/补偿和审计，不开放任意 SQL。
- 写入测试只使用负责人标明可丢弃的隔离测试记录，不触碰真实临床数据。

## 7. 持久化和生命周期

现有 live_apps 只是覆盖保存，目标模型尚未实现：

| 对象 | 目标内容与约束 |
| --- | --- |
| connections | 平台 origin、获准数据源引用、凭证引用；不存密码 |
| user_preferences | 最近选择；与应用固定数据绑定分开 |
| apps | owner、草稿指针、发布指针、归档状态 |
| app_versions | 不可变 Spec、hash、字段/画像指纹、生成部署/版本、能力快照 |
| jobs | 幂等请求 hash、owner、conversation/run、游标、状态、重试和错误 |
| audit_events | 来源身份、动作、实体引用、版本、结果、审批与上游审计关联 |

生命周期：草稿 → 校验通过 → 用户发布 → 固定版本运行。修改产生新草稿；回滚只切应用定义，不回滚业务数据。

画像变化执行兼容性检查。新增不使用字段可不阻断；缺字段、类型/主键/敏感策略变化应阻止相关操作并要求迁移确认，不能把最新样例静默套进旧规格。

四种保存边界要说清：

- 应用定义和绑定引用持久化。
- 不默认创建本地业务记录副本；缓存需明示范围、保留期和加密。
- 当前完整需求和模型回复会保存，用户粘贴患者数据也会落本地并发送上游。
- 完整业务审计与不可变版本是目标能力，尚未具备。

所以“不建业务表”不等于“没有医疗信息落地”。目标必须包括默认不发送临床行、输入脱敏/提示、日志最小化、加密、保留期、访问审计和可验证清理。保留期由医院数据负责人确认。

## 8. 安全和可靠性

- 生产 HTTPS；开发 Token 仅内存，生产凭证由后端密钥管理托管，退出/过期失效。
- 每租户/用户有稳定不透明 Visitor ID，不全员共用，也不含姓名、住院号。
- 所有者、CSRF/Origin/Host 检查覆盖全部接口；正式运行默认不挂载缺乏同等保护的 legacy CRUD。
- 元数据与运行权限可撤销；权限撤销不能只等前端刷新。
- 内部 SSE 游标可能是不透明字符串；External 是整数 seq，两个解析器分开。
- 保存最后已处理游标并去重；幂等操作同键重试，未知是否受理时先查状态，不重复创建 Run。
- 重启作业标 interrupted/待恢复，有确切上游坐标后再恢复，不自动重发可能已受理请求。
- 超时、取消、退避、并发限制、消息/产物上限；错误和日志脱敏。
- 建立数据库迁移、加密备份、WAL 一致性备份与恢复演练；开发服务器不直接公网部署。

## 9. 实施关卡

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| A：纠正现状 | 隔离 legacy、样例标记、能力按钮、连接恢复 | 浏览/刷新不误改绑定；无实时/CRUD 虚假承诺 |
| B：外部接入 | 负责人指定隔离部署/固定版本，经正常授权配置 API origin/凭证/工具 | 一条非临床探针完成状态/事件/最终消息/历史；访客隔离和版本有证据 |
| C：可发布生成器 | Spec、可信绑定、不可变版本、草稿/发布、三部分 UI | 生成/修改/发布/重启/重开一致，不执行模型代码 |
| D：真实查询 | 获准 QueryGateway、筛选/分页/详情 | 有远端查询和权限、游标、数据时间证据，不是画像样例 |
| E：受控 CRUD | 获批实体表单和领域操作 | 提交、校验、幂等、冲突、确认、审计、失败恢复均通过 |

A/C 本地工程可在 B 阻塞时继续，但 mock/离线成功不能算 B/D/E 完成。不会在预检失败时反复调用模型。

验收矩阵：

- 离线：字段/权限拒绝、版本不覆盖、幂等、持久化、会话隔离、恶意内容、结构变化。
- UI：目录第二页选择恢复、重新登录恢复、浏览不改绑定、草稿/发布区分、空/错/加载态。
- External：Conversation/Run/历史/SSE；同键冲突、跨访客访问、取消、重连、过期和限流。
- 查询：固定结果集分页无重复遗漏，权限撤销，主键详情，筛选排序和总数语义。
- 写入：仅获准的隔离测试数据，验证拒绝、成功、冲突、审计和恢复。
- 运维：重启、迁移、备份还原。当前 16 项测试仅覆盖原有本地逻辑，不证明以上关卡通过。

## 10. 本地复用与实际缺口

可复用：真实适配、内存 Token、SSE、多轮、取消、幂等、字段白名单、SQLite；保留受控渲染，不执行模型代码。

需重构：

- 全局固定 External Visitor、只凭 Key 就切协议。
- live_apps 覆盖保存，缺发布模型、运行版本锁定。
- 连接保存只校验来源，缺精确表/画像校验。
- legacy CRUD 与真实路径共用服务，但鉴权/审计边界不同。
- 完整需求/回复落盘，缺医疗信息保留和清理政策。

需修 UI：

- 只取目录第一页导致恢复成别的表。
- 重新登录未正确恢复连接；查看表即保存。
- 清除只清内存；刷新重新恢复。
- 画像变更只提示，旧 Spec 仍套最新样例。
- “查看”仅 toast，CRUD 仅外壳；样例被描述为最新数据。

这些问题本轮只审计和制定修复计划，未修改运行代码。

## 11. 最近的阻塞和需要的决定

请平台负责人指定一个用于本项目的隔离测试部署及固定版本，并经正常授权配置有效凭证/API origin，明确允许的工具与数据范围。

没有该决定，不启用/创建凭证，不扩大访问、不修改旧客户端、不运行临床工具。元数据、实时查询、业务写回分别设权限和验收关卡；系统能力取决于契约和授权，不取决于 Agent 的名称。
